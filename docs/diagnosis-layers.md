# 诊断层详解

IconDoctor 的核心不是"修"，是"定位"。每一层都要求**可判定的证据**，
不允许出现"可能是缓存问题，试试清一下"这种结论。

## 层与探针

### L1 · 图标源（Icon source）

**问**：这个程序本身还有图标资源吗？

**探针**：`ExtractIconEx(target, 0, ...)`，直接读 PE 资源，**不经过 shell 缓存**。

**判定**：
- 返回句柄 ⇒ Pass（图标源存在）
- 返回 0 ⇒ Warn（程序没图标，任何缓存操作都修不了）

这一层的意义：先排除"根本修不了"的情况，避免后续白折腾。

### L2 · 快捷方式内容（Shortcut content）

**问**：`.lnk` 本身还完整吗？

**探针**：`WScript.Shell.CreateShortcut()` 读 target / arguments / working directory。

**判定**：
- target 可解析且文件存在 ⇒ Pass
- target 为空 ⇒ Warn（link 数据损坏，需要重建）
- target 指向不存在的文件 ⇒ Warn（卸载残留）

### L3 · 图标缓存（Icon cache）

**问**：缓存数据库坏了还是满了？

**探针**：枚举 `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db`，
读 `HKCU\...\Explorer\Max Cached Icons`。

**判定**：
- 32/48 数据库大小是 2 的整数次幂（1MB/2MB/4MB…）且未设置上限 ⇒ Warn（写满了）
- 数据库不存在 ⇒ Warn（下次启动会重建）
- 其它 ⇒ Pass

> 注意：这一层只能解释"新图标变白"，解释不了"特定几个图标一直白"。

### L4 · Shell 处理器（Shell handler）

**问**：`.lnk` 的图标处理器还注册着吗？

**探针**：
1. `HKCR\lnkfile\shellex\IconHandler` 的默认值（应为 `{00021401-...}`）
2. `HKCR\CLSID\{00021401-...}\InProcServer32` 指向的 DLL 是否存在（`windows.storage.dll`）

**判定**：任一环节缺失 ⇒ Fail。

这一层坏了的典型症状是**所有**快捷方式都没有图标，而不是个别几个。

### L5 · 文件夹对象（Folder object）

**问**：是不是这个目录本身在污染图标解析？

**探针**（控制变量法）：

1. 在目标目录里创建一个临时 `.lnk`，指向已知正常的 `notepad.exe`
2. 取它 shell 给的图标，判断是否白纸
3. 在 `%TEMP%` 里创建**同样的** `.lnk`，做同样的判断
4. 对比两个结果

**判定**：
- 目录内白、`%TEMP%` 正常 ⇒ **Fail**（目录对象损坏，这是清缓存永远修不好的那种）
- 两边都白 ⇒ Warn（不是这一层，回去看 L3/L4）
- 两边都正常 ⇒ Pass

探针文件在 `finally` 里删除，不会留下垃圾。

### L6 · 文件夹 ACL（Folder ACL）

**问**：目录权限里有异常规则吗？

**探针**：`Get-Acl`，找两类东西：
- `Deny` 规则
- `S-1-4-*` 开头的孤儿 SID（非唯一权威，通常是重装系统/换账户的残留）

**判定**：存在任一 ⇒ Warn。这类 ACL 本身很少直接导致白纸图标，
但它会让后续的修复（改名、移动、重建）莫名其妙失败，值得单独报出来。

## 判定顺序的意义

从 L1 到 L6，是**从"改不了"到"能改"、从"只读"到"侵入"**的顺序：

- L1/L2 是只读检查，结论如果是"程序没图标"，就应该直接结束
- L3/L4 是系统级状态，修复成本中等（重启 explorer / 重注册组件）
- L5/L6 是目录级状态，修复成本最高（搬文件），必须显式确认

`Invoke-IconDiagnosis` 会把六层全部跑完（方便贴 Issue），
但 `RootCause` 只取**第一个** Fail/Warn 的层——因为外层坏的时候，
内层的结论是不可信的（比如 L5 坏了，L3 看上去也会"像缓存问题"）。

## 相似度阈值是怎么定的

判定是**两段式**的，顺序很重要：

**第一段：相似度**。`Compare-IconSignature` 输出 0–1 的相似度，
`>= 0.80` 直接判 `Ok`——不管它看起来多白。

原因是实测数据：纯白底的正常图标（百度网盘 0.978、搜图神器 0.981、
个人中心 0.975、微信开发者工具 0.936）相似度都很高。如果先看白色占比，
这些全会被误判成白纸。

**第二段：白纸启发式**。只有相似度掉到 0.80 以下，才启用：

```
WhiteRatio >= 0.45  AND  Saturation <= 0.18
```

实测的"真白纸"（快捷方式图标指向不存在的 ico）长这样：

| 指标 | 真白纸 | 正常白底图标 |
|---|---|---|
| Similarity | **0.622** | 0.936 – 0.981 |
| WhiteRatio | 0.67 | 0.55 – 0.75 |
| Saturation | **0.035** | 0.057 – 0.174 |

可以看到：**白色占比两者几乎一样**（0.67 vs 0.75），真正把它们区分开的是
相似度和饱和度。这也是为什么单看"白不白"的检测一定会误报。
